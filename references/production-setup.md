# Set up Lane in production

Use the deployed version containing Canvas library, Team Quick Start, scoped team MCP and Inkbox briefing support. Keep this distinct from a live-provider acceptance result: the local fixture cycle uses simulated providers.

1. Open Lane → Playbook Studio → New team. It opens empty in Quick Start. Existing teams keep their current canvas. The question-mark button opens Quick Start again.
2. Create the one-hour **team setup key**. Install `persona-team-manager` from `https://github.com/Gabriel-Operator/persona-team-manager`. Copy the team connector URL and MCP settings to your coding assistant. Keep the key in its credential settings. A cloud assistant needs the production HTTPS URL, not localhost.
3. Copy the interview prompt from Quick Start. Explain the meeting preparation and follow-through workflow. The assistant exports current definitions and merges `assets/lane-studio-teams.json` without changing unrelated teams. It previews and commits the reviewed proposal, preserving existing IDs, revisions and head. Keep automatic work off during setup. Set a budget explicitly as the owner; the sample's team budget is zero.
4. In Lane → Connectors → Add connector, add **Google Calendar** and **Gmail** as your personal accounts. The managed path is **Use a managed connection → Load my managed accounts and operations → Connect another managed account**. If prompted, add your Composio project key in account settings first. Complete Google sign-in yourself. Choose only the required calendar/email read operations. The alternative official remote MCP path uses its supported account authentication. Do not paste tokens into a conversation.
5. Add **Notion** separately. Give the integration access to the disposable Contacts database only. Select that database in the installation's immutable resource mappings. The owner maps it as the shared app destination; personal email/calendar access remains separate. Map exact attendee email → existing Notion page and current revision → existing Lane lead and current revision using `map_meeting_contact`. The database URL alone does not establish those row identities.
6. For the call, use **Inkbox**, with no Vapi account. In Lane’s AI Resources, connect the persona’s Inkbox identity, dedicated voice-capable number and webhook signing key, then enable it in **Phone calls**. Set destination pricing for the country prefix. The team respects the existing published phone capabilities and any stricter team resource policy. `briefing_phones` lists ready permitted identities; `bind_briefing_phone` maps one to the `briefing` requirement. Verify your own profile phone first. Other members must use their own private calling connection; they cannot borrow the owner’s persona identity.
7. For capture, use an authenticated remote MCP adapter that actually supplies meeting scheduling and transcript retrieval. **Recall’s official MCP does not currently supply meeting-bot creation**: it is mainly for investigation and webhook configuration. A Recall REST-backed remote MCP gateway is needed for the scheduling operation. Reuse an already available transcript source instead if attendance is unnecessary. The capture contract must confirm the exact meeting link, allowed recording permission, completed meeting time and nonempty transcript. Enroll only specific meeting links after participants consent.
8. Map discovered operations and normalized result fields. The logical names `upcoming`, `search`, `call`, `status`, `schedule`, `transcript` and `update` are not assumed provider tool names. `assets/lane-meeting-resources.json` describes the normalized contracts and shared destinations. Test mappings against sanitized samples. An MCP with insufficient semantics stays unavailable.
9. Register the Meeting cycles List, reuse Lane’s Leads/relationship Lists, and add the Meeting cycles data point to the workspace configuration through its normal definition editor. Configure `meeting-cycles`, `leads`, `relationship-meetings`, `relationship-observations`, `relationship-outcomes` and `live-results` publisher grants with `configure_publisher`. Select an existing shared team page for the last destination. No page ID, credentials, phone number or real meeting URL belongs in Git.
10. Review the Canvas: watcher, goal researcher, caller, scribe, analyst and steward. The publisher is a reusable supporting playbook. The Canvas library supports Add, drag-and-drop, editing and removing a bot while retaining its definition. Review source-sharing fields explicitly; every private source grant must permit the fields that will enter Notion, Lists and shared pages.
11. The owner enables background work and activates the exact meeting policy. Each member separately joins recurring work with their own accounts, verified phone and consented meeting links. Registration and enrollment do not grant another person's accounts. Effect reviews remain separate. Missing account setup appears as a targeted conversation request; a text reply saying “connected” does not satisfy it.
12. Create a dedicated test Calendar event and relevant test email. Allow the five-minute watcher to discover it, with preparation 30 minutes before the meeting. Review the exact call and capture effects. Confirm one briefing call (maximum three minutes), consented capture, transcript completion, registered signal receipt, one Notion write, Lane lead status/notes and shared page/List updates. Revoke a source and verify the correct member is asked to reconnect without replaying a completed effect.
13. Capture the successful goal researcher’s procedure, have the owner review/adopt it, and repeat with a second test meeting and fresh inputs. Inspect private run receipts and the task tree from Canvas. Verify provider results and cleanup separately from fixtures.
14. Revoke the one-hour setup key in **Audit logs → App access**. It expires automatically as well. Keep provider connections only as long as needed for ongoing work.

Reference provider contracts: [Inkbox calls](https://inkbox.ai/docs/api/phone/calls), [Recall MCP capabilities](https://docs.recall.ai/docs/mcp), [Recall recording control](https://docs.recall.ai/docs/recording-control). Signed provider callbacks must be verified by their existing connector ingress; the meeting cycle uses authenticated completion polling and does not accept unsigned callback bodies as evidence.
